# Evidence: the migration tool is not telecom-specific

`migrator/` contains no telecom literal (no `call`, `subscriber`, `tower`,
`cdr`, ...) anywhere under `ssis2nifi/`, `catalogue/`, `jobconfig.py`,
`bindings.py`, `sidecar.py`, or `cli.py`. The only place any of that exists
is `jobs/telecom_cdr/job.yml` and the `.dtsx` package it names.

## Proof, not assertion

`jobs/_smoketest_l1/` is a **read-only copy** of `L1.dtsx` from the reference
repo's `converter/corpus/packages/` — a real orders/currency-conversion
package, unrelated to telecom, that the reference repo's own converter
already handles. Converting it through this repo's tool, unmodified:

```bash
$ python3 migrator/cli.py analyze jobs/_smoketest_l1 --no-graph
package: Lesson 1   (Microsoft.Package, format 8, friendly dialect)
connections: 2 (1 FLATFILE, 1 OLEDB)
control flow: 1 task(s), 0 precedence constraint(s)

dataflow "Extract Sample Currency Data": 4 components, 3 paths

coverage: 4/4 convertible, 0 need manual review

$ python3 migrator/cli.py convert jobs/_smoketest_l1 -o out/_smoketest_l1
coverage: 4/4 components recognised
wrote out/_smoketest_l1/_smoketest_l1.flow.json
  6 processors, 10 connections, 6 controller services
  wrote out/_smoketest_l1/_smoketest_l1.mapping.json
  1 sensitive propert(ies) left null; see _smoketest_l1.secrets.json
```

`jobs/_smoketest_l1/bindings.generated.yml` (gitignored, regenerated by the
command above) was produced purely from `L1.dtsx`'s own connection managers
and `jobs/_smoketest_l1/job.yml`'s deployment target — no code path specific
to this package or its domain was touched. `out/_smoketest_l1/_smoketest_l1.mapping.json`
correctly records `dbo.NewFactCurrencyRate`'s six columns (`AverageRate`,
`CurrencyID`, `CurrencyDate`, `EndOfDayRate`, `CurrencyKey`, `DateKey`) —
discovered from the package's own `OpenRowset`/column properties, not typed
anywhere in this repo.

Run the telecom job through the exact same commands
(`migrator/cli.py analyze jobs/telecom_cdr`, `migrator/cli.py convert
jobs/telecom_cdr`) and you get 17/17 components, 29 processors — a
completely different shape, same unmodified code.

## What DOES change per job

Only `job.yml`:

| Fact | Where it comes from |
|---|---|
| Deployment target (DB URL, landing dir, NiFi URL) | `job.yml`'s `destination_db`/`nifi` blocks |
| Which table is the ledger, which are rejects | `job.yml`'s `ledger` block |
| Which tables/columns the report compares | `job.yml`'s `compare` block, resolved at report time via `information_schema` -- not typed as a column list anywhere |
| Every other table/column name (the actual data shape) | discovered from the `.dtsx` itself, at parse time |

## Vendored-and-verified, not just vendored

`migrator/tests/` runs the reference repo's own bindings-free unit tests
(dialect parsing, refId layering, expression compilation, IR round-trip,
lineage/disposition classification) unmodified against the vendored code,
plus three new tests (`test_ledger_generalization.py`) proving the one file
that WAS edited (`emit/flowdef.py`) behaves as claimed: no `_add_alerts`
function exists any more, the job-ledger is silent unless a job configures
one, and the ledger's table name in the generated SQL is exactly whatever
`job.yml` said -- checked against a deliberately unusual name
(`some_other_schema.totally_different_ledger_name`) to rule out any
lingering hardcoded default.

```
$ python3 -m pytest migrator/tests report/tests -q
...
69 passed
```
